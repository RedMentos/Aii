## Finding: C6 commit point and visible first byte must remain coupled
The Run78 prereg proposes that a successful controlling-TTY challenge atomically transitions a C5/F3 DRAFT to `OUTPUT_COMMITTED` **while explicitly sending no candidate bytes**. The existing `v13/code/v13/transaction.py::commit_output` documents `DRAFT -> OUTPUT_COMMITTED` as the commit point **right before the first visible byte**; Canon IH-H12 similarly binds the output commit point to the first visible byte, and W8 requires truthful persistent partial-output/restart state.

**Concrete crash counterexample (logical, not executed):** Human approves a local challenge; DB transaction marks message `OUTPUT_COMMITTED`; process dies before any output stream begins. On restart, transcript claims output was committed even though no first byte was visible. The normal DRAFT replacement path is closed and a late correction might be treated as the only valid edit. This is an inconsistent lifecycle even if the source/TTY checks are otherwise correct.

**Recommendation to owner (not a unilateral redesign):** Keep source/TTY authorization and one-time approval as a separate, time-bounded `APPROVED_TO_DELIVER` capability/receipt that does not claim output. Only the actual stream owner may perform `DRAFT -> OUTPUT_COMMITTED` at its first-byte boundary, rechecking the same source/approval binding under transaction, and must have a crash/restart receipt distinguishing zero emitted bytes from partial output. If atomic first-byte + SQLite is impossible, explicitly document the unavoidable crash window and conservative recovery status rather than labeling unseen text committed. This preserves Canon function, human approval and safety gates.

**Additional review condition:** Per-call TTY consent cannot be reused after any source/candidate mutation, session change, generation change, cancellation, `:stillstand`, or approval timeout. A synthetic PTY test is not human approval proof. No automatic tool dispatch or learning rights.

**Evidence level:** static comparison of exact prereg commit and existing `transaction.commit_output` source; no executed Run78 test, no production assertion. **Next:** inspect Run78 implementation/CI when owner pushes; construct a real SQLite crash-window counterexample and ensure first-byte ownership is explicit before integration. **No promotion:** Age0 RECORD_ONLY, STEP2 UTILITY_FAIL, B3 NO_PROMOTION, JEPA/Redmi/full-system gates unchanged.
