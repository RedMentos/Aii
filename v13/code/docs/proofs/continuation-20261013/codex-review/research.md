# Bounded process lifecycle research, 2026-10-13

Primary sources accessed 2026-10-13: [Python 3.13 subprocess](https://docs.python.org/3.13/library/subprocess.html#subprocess.Popen) and [Python 3.13 os.killpg](https://docs.python.org/3.13/library/os.html#os.killpg). Current documented scope: POSIX start_new_session calls setsid before exec; killpg sends a signal to that process group. This supports owned-group cleanup, not control over descendants that deliberately establish another session. No third-party code was copied or dependency/model changed; Python stdlib plus existing NumPy only.

Against automatic success: Python subprocess timeout alone describes the child process; software cleanup does not prove Android power-loss durability, availability under the actual Termux build, or thermal/resource limits. Direct original-handler reproducer here uses a synthetic sleeping installer, no native inference. Candidate also tests a TERM-resistant child after its leader exits and an unrelated process remaining alive.

Redmi baseline: use the independent bounded shell entrypoint against installed pinned resources, retain wrapper and original device-check reports; interruption must stop the owned native group and preserve partial evidence. Ablation is the unchanged original phone handler against the same simulated stall. Result that would change integration: unsupported process-group/dir-fsync behavior on device, a leaked owned descendant, source drift, or failed native gates. Until actual device evidence, Linux software lifecycle only. Installation/model identity and numerical parity are still delegated to the original phone driver; no gate is weakened.
