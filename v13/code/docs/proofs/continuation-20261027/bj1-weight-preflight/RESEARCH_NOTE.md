# WP-BJ1 numeric preflight research and scope

Access date 2026-10-27 UTC. Primary source: PyTorch official `torch.get_default_dtype` documentation, https://docs.pytorch.org/docs/stable/generated/torch.get_default_dtype.html (default floating dtype initially `torch.float32`), and official `torch.finfo` reference https://docs.pytorch.org/docs/stable/type_info.html (finite range and smallest normal value). Source status: current framework documentation; it does not validate V13's learning utility.

V13 mapping: `BodyJepaTrainer.fit` currently creates `torch.tensor(wts)` without an explicit dtype for CE and sends the same values to `jepa_loss`. The registered CPU baseline assumes the default float32. Python `math.isfinite` alone is insufficient: a Python-finite weight can overflow or underflow on conversion, or a finite list can have an infinite float32 sum. The candidate preflight uses standard-library IEEE-754 float32 packing to reject such inputs before a model is loaded; it preserves original valid numeric values and does not import torch just for validation.

Counterpoint: PyTorch permits changing the default dtype. This preflight is intentionally conservative for the current float32 CE path, **not** a universal rule for every future mixed-precision trainer. If a future explicit float64 weight tensor is approved, update the dtype-bound contract and preregister a separate cohort rather than silently weakening this guard.

Small Redmi-testable baseline: use a fixed 3-item batch with weights `[1.,0.,2.5]` and compare CE and JEPA loss/gradients before and after the preflight under identical master, seed and item hashes. No optimizer run is needed for the boundary test. Ablate negative/NaN/Inf, float32 overflow and underflow, and positive/zero mixtures. Failure modes: non-default torch dtype, subnormal flush-to-zero, all-zero effective weight, a huge integer raising during float conversion, or a modified caller bypassing `fit`. Evidence here is only software preflight, **not** improved learning, retention, or model utility.
