# WP-BJ1 numeric representation addendum — preflight must match CE tensor dtype

Date 2026-10-27 UTC. This addendum precedes the next test/source patch. The registered BodyJepaTrainer CE path creates `torch.tensor(wts)` with default float32, so Python-finite weights such as `1e100` become float32 infinity, and all tiny positive weights such as `1e-300` become float32 zero. Both can produce invalid CE even when Python `sum(weights)` is finite and positive. Extend the existing preregistered overflow/zero-sum counterexamples to the actual float32 representation. Test these values before changing source; reject unrepresentable or zero-effective-total weights **before** loading a model. Preserve legitimate weights unchanged and avoid importing torch just for preflight. No change to source/model/cohort, no authority promotion.
