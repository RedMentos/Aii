## Reproduced gap and bounded fix
The Run22 `python -I -S` bootstrap disables Python site/.pth startup, but it **does not** disable ELF dynamic loader constructors. A private gcc-built shared object injected with `LD_PRELOAD` wrote a sentinel **before** the helper reached its deliberately nonexistent `cgroup.procs`. The counterexample ran on Linux; it is **not** a real writable-cgroup test. Original guard regression: four failing LD_* subtests. Independent review identified empty-valued LD_* semantics, adding two failing subtests. All RED evidence preserved.

Isolated candidate patch adds `reject_prejoin_loader_env`: reject **any present** LD_* key, including empty values; do not strip or rewrite native runner environment. The launcher validates a snapshot and passes exactly that snapshot to `Popen`, closing a check/use environment race. The preregistered runner, model, seeds and fixture hashes are unchanged. This is not production-integrated.

## Critical limitation
This guard is **not** atomic cgroup containment. ELF DT_NEEDED/DT_AUDIT constructors and system loader preloads can still execute before the helper joins the cgroup. For a stronger claim, evaluate `clone3(CLONE_INTO_CGROUP)` (Linux 5.7+) or a separately proven bootstrap. Do not promote containment, STEP2, B3, Body-JEPA or full V13 gates from this partial fix.
