# Run55 preregistration amendment — action-control readout alignment

2026-10-28, before Run55 CI/PR or any native/utility claim. The initial Run55 prereg described fitting both readouts from `model.predict(X_train,A_train)`. On independent methodological review this would leak the **true train action labels** into the shuffled-action control's supervised ridge decoder even though that WorldJEPA control was fitted on shuffled actions. A decoder could learn a route effect from untrained/random action sensitivity, making observed-vs-shuffled attribution misleading.

Amend the control only: reconstruct Run51's effective seeded action permutation from the registered train arrays; if the first permutation leaves one-hot actions unchanged, use the same roll fallback. Verify its SHA256 equals Run51's `action_permutation_sha256` and that actions actually change. For `shuffled_train_action`, compute **train** predicted latents using the same shuffled train actions that fitted that model, while **holdout** predicted latents use original holdout actions (same heldout task). The observed-action model uses true train and holdout actions unchanged. Fit both ridge readouts on their respective train predicted latents and observed train outcomes; never train on heldout outcomes. This improves the negative control but still does not prove causal JEPA utility. No change to Run51 or Run54 source/seed/fixture.

Add a focused negative test that monkeypatches `WorldJEPA.predict` to inspect which training action matrix reaches the control readout, without changing the original source. Exact-head CI must report aggregate metrics and all negative gates remain unchanged.
