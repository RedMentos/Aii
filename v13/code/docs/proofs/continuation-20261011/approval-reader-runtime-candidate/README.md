# Isolated approval reader candidate

This candidate closes the recorded same-process Runtime reader race without changing any frozen live runtime file. It has not been integrated or used with model inference. The original filesystem-only race report and tests remain unchanged.

Runtime injects its existing Store into RunnerPool. The pool forwards the Store to ordinary generation and same-causal template runners. While holding that Store's RLock, the runner compares the filesystem mirror with the committed AdapterRegistry. An ACTIVATING mirror that differs from committed state is refused, including failed mirror recovery. It validates the existing LoRA and sparse-memory bindings, copies admitted adapter/memory/sidecar bytes into a private per-load directory, verifies each copy against the approved hash, and makes copied files read-only. Child arguments and V13_MEMORY_FILE point to those copies. The loaded delivery provenance continues to identify the original approved source binding; `_launch_assets` identifies the actual files opened by the child.

The Store lock is released before Popen, native cold load, and health polling. After health, a guarded check verifies the committed mirror and copied bytes before publishing a loaded binding. Original adapter paths and all copied paths participate in lifecycle stamps, so rewrites invalidate warm reuse. Unload and failed load remove the snapshots. Cancellation after waiting for an approval is checked before Popen.

The copies address the interval between Popen returning and the child opening an adapter or memory file. An original path replacement at that boundary cannot change the bytes passed to the child; persistent original changes still reject the health handoff. This does not make filesystem and SQLite globally atomic. External `runner_lora_args` calls and runners constructed without the injected Store retain their earlier behavior. It assumes trusted local files: model/native library mutation by unrelated writers is still covered by existing lifecycle checks, not immutable model/library copies. Abrupt parent termination can leave temporary snapshot directories; ordinary unload/failure cleanup is covered. This grants no learned quality, activation permission, or semantic truth authority.

Lock order: runner asset admission takes Store.mutex only. RunnerPool's existing mutex can allocate runners but does not take Store.mutex, and approval does not enter RunnerPool or Runtime locks. There is no Store-to-Pool lock edge introduced. Real tests verify that a separate thread can acquire Store.mutex during Popen and health requests.

Nine isolated tests pass with real SQLite and authored loopback child processes: deferred COMMIT failure with a blocked reader, successful approval and restart, failed-recovery mirror mismatch, original path replacement before child-open, Store availability during startup/health, actual Runtime/pool/same-causal-template forwarding, cancellation while waiting, copied-byte hash failure, and sparse memory/sidecar snapshot provenance and cleanup. No native model inference, training, or production activation ran.

Integration is deferred until the frozen 16-row source-handoff cohort finishes. Require the two live source hashes to match `approval-reader-runtime-baseline/manifest.json`, then compose reader transform first and firing transform second. Both preserve the firing transform anchors and compile together. Future phone packaging must include this baseline's runners.py, runtime.py, and manifest.json (three immutable fixture files), in addition to the existing firing fixtures. Run the complete suite on the composed integrated source before packaging.
