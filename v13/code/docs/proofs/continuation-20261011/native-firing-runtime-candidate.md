# WP-T9 request-scoped native firing candidate

The retrieved Drive roadmap leaves delivery of a fact as Trace versus Exact open. This candidate connects the existing opt-in native audit parser to the actual completed Runner request and records a source-bound SHADOW map. It does not omit Exact, change numeric memory writes, activate selective delivery or certify useful learning.

The four live modules remain byte-identical to their archived baseline. The hash-bound helper renders the review patch and loads isolated modules for offline regression. Store is included because its existing telemetry whitelist otherwise discards firing observations; the initial failing test is retained.

The opt-in is `runner.cfg['native_memory_audit']=True`, currently programmatic. The public config schema/defaults are intentionally unchanged while Dream binds `v13/common.py`. Only an approved sparse-memory generation child receives the audit environment flag. Warm reuse notices a changed audit setting. Ordinary runs carry no new firing metric.

A request window begins after template/tokenization and immediately before completion. The child PID, log inode/offset and healthy loaded delivery binding are captured. A terminal SSE stop is required. Cancel/error, missing evaluation, ambiguous requests, malformed counters, log rotation/truncation, changed binding and multiple native steps return unavailable. A real loopback HTTP server fixture verifies the actual completion stream boundary; it is not a real model.

Observed slot writes are matched to the currently approved native sidecar rows only after the existing native/source/content checks. Final revalidation catches forget/reapproval during mapping. Forgotten, inactive, deleted or source-conflicting facts cannot become observed fact IDs. All observations retain Exact and explicitly deny semantic truth, quality or activation authority.
