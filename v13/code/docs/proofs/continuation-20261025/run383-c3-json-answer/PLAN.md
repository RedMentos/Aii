**Technical hypothesis:** Run382 actual pinned Linux-native C3 produced 4/12 empty answer fields per arm; field confidence unavailable for those. `BodySolver.SCHEMA` permits an empty string (`maxLength:64`, no `minLength`), while llama.cpp JSON schema is not necessarily visible to the model as prompt text. Test whether requiring `minLength:1` in the grammar and explicitly describing JSON in the system prompt improves *correct* final answers, rather than merely forcing wrong nonempty strings. Source context: upstream ggml-org/llama.cpp grammars README documents JSON Schema → GBNF subset and string minLength; issue #30749 (2026-10-18) warns length bounds may be lost when combined with a pattern; this experiment uses no pattern. Exact b10964 behavior is to be measured, not assumed.

## Fixed 2×2 arms, no after-the-fact tuning

A `baseline`: existing `v13.agi.solver.SYS` and `SCHEMA` exactly. B `min_length`: same SYS, copy of SCHEMA with `answer.minLength=1`. C `explicit_json`: new fixed system prompt **`Return only a JSON object with one key named answer containing the exact short final result as a nonempty string. No explanations, no extra fields, no surrounding text.`** with original SCHEMA. D `combined`: C's system prompt + B's minLength schema. Each item uses the same user prompt across arms; rotate arm order by item index to control warmup/position. Temperature 0, seed13, 512 context, 40 answer tokens, 2 threads, same `confidence_field='answer'`, no history/tools/memory/teacher/training.

Fresh **12 tasks** not used in Run373 or Run382: arithmetic `Compute: 6 + 8 = ?`→14, `Compute: 15 - 7 = ?`→8, `Compute: 4 * 5 = ?`→20, `Compute: 13 + 9 = ?`→22; reverse `Write backwards: bird`→drib, `Write backwards: rose`→esor, `Write backwards: moon`→noom, `Write backwards: train`→niart; sequences `Continue: 2, 5, 8, ?`→11, `Continue: 4, 8, 12, ?`→16, `Continue: 9, 7, 5, ?`→3, `Continue: 1, 4, 7, ?`→10.

**Primary PASS only if combined vs baseline**: >=2 more exact answers /12; >=2 fewer empty answer fields /12; no category regresses; number of wrong nonempty answers <= baseline; answer-field confidence count >= baseline; combined mean duration <=1.5x baseline; all 48 calls FINAL, CAN_TRAIN_BODY false, native process reaped with zero PIDs. B/C standalone are diagnostics only, cannot be selected post hoc. If any criterion fails, `RUN383_JSON_ANSWER_NOT_SUPPORTED`, no production change. Preserve failures and raw outputs. Even PASS would be a tiny Linux-native study, not STEP2/B3/Body-JEPA/jepa_weight/Redmi/V13 acceptance.
