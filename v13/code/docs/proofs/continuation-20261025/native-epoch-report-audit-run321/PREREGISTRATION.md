## Defect hypothesis and acceptance

Run320 `select` validates only cohort **length**, not exact question identity/order, and trusts summary scores without recomputing raw answers. A permutation or incorrect summary can silently hide a previously-correct retention probe loss or claim a candidate PASS. An independent read-only audit of the published Run320 JSON must reject these cases. It must not promote a model or change the preregistered training/evaluation.

Freeze before implementation: compare exact ordered `FACTS`, `PARAPHRASES`, `NEAR_MISS`, `PROBES` question identities against the original source-bound cohort. Recompute every `ok`, `leak`, `strict` bit from the raw `a` text and frozen keyword lists using the original Run320 evaluator's `hit`/`first_sentence` functions; recompute `summary`, invalid count, retention loss and `select`. Fail on missing/extra/reordered/duplicate questions, forged scores, invalid types, tampered summary, altered selection, missing epoch/receipt SHA correspondence, wrong gates or status. Require the report's own exact master/epoch hash receipts but **do not** claim that these JSON-reported hashes independently verify inaccessible GGUF bytes. Audit is source-only/fixture and cannot establish native training. Preserve raw FAIL reports unchanged.
