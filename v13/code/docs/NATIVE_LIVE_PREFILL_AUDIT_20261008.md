Source archive retrieval, bounded GGUF header inspection and aggregation of already saved real Linux measurements are the only operations. A feasible port below is **not an implemented capability**, nor sparse-body learning, train masters, receiver injection or JEF native continuity.

The immutable single source remains `docs/canon/V13_v10.16.1_WORK_HANDOFF_SINGLE_SOURCE_B3_HARDENED.md`, SHA-256 `3423906b01b24443fcef733fb5c7ef47296963df63e603d8f843c99d544877ee`.

## Result

A causal generation graph already contains the final normalized LFM2 hidden state immediately before its vocabulary projection. It is technically plausible to read that state and the first-position logits in the **same** prefill while retaining the existing process and memory. The current Python/HTTP BodyPort cannot do this. Merely enabling `--embedding` or calling the two exported getters does not establish simultaneous availability on the pinned LFM2 implementation.

The smallest exploratory native change is a carefully bounded `cb_eval` observer of the existing `result_norm` tensor during normal completion. A production port could instead introduce a narrowly scoped hidden-output extraction flag independent of the existing embedding mode. Either still requires actual build, numeric parity, continuation, cancellation and cache tests. Applying an external state-conditioned delta **before** the first token additionally requires a controlled pre-sampling pause/resume or bounded adapter execution at that native boundary; returning a hidden vector after the first token has been sampled is too late.

### Causal attention and pooling

The comment in current `LlamaRunner.load` calls the embedding prefill “Noncausal”. That is not established by the actual pinned configuration. `common/common.h` defaults `attention_type` to UNSPECIFIED; `common.cpp` forwards it. `llama-context.cpp:223–228` then inherits the model setting. `llama-hparams.h:226` defaults causal attention to true, and `llama-model.cpp:1232` optionally replaces it from GGUF metadata. Bounded header inspection of the installed C3 1024D and B1 2048D LFM2 GGUFs found **no causal-attention or pooling metadata override**. The existing command adds `--embedding --pooling none`, but does not change attention type. Therefore source/config inspection supports **causal model-default attention** for these pinned artifacts; a numeric same-live-prefill comparison remains unperformed. Do not use the misleading comment as proof of noncausal states, or silently flip a mask to chase parity.

`LLAMA_POOLING_TYPE_NONE` preserves per-output token states; server embedding responses do not apply embedding normalization when pooling is none. Final RMSNorm already belongs to the model. Mean/CLS/last sequence pooling or an extra vector normalization changes the feature contract. Existing Python local unit-normalization for an external learned head is separate from the stored native state.

Noncausal contexts have the native assertion `n_ubatch >= n_tokens_all`; causal contexts can prefill chunks while carrying attention and LFM2 short-convolution recurrent memory. Current C3 tap uses physical 512/512 while generation uses 128/128. This discrepancy is another actual parity question, even under a causal mask. Do not claim a 512-token monolithic tap equals a 128-token chunked generation from configuration alone.

## Minimal actual port work, within existing BodyPort

1. **Read-only boundary first.** Keep ordinary generation mode and causal mask. For a proof build, configure `cb_eval` before context creation, ask only for the exact `result_norm` node on the final prompt output, validate type/shape/strides and copy only its selected final 1024D C3 row. Scope the observer to the request and bind it to physical process/start identity, slot/sequence, prompt token hash, positions, model/binary hashes, rule/context generation and current cancellation/deadline. Reject missing, duplicate, stale or mismapped captures; do not retain naked `ggml_tensor*` or getter pointers across graph reuse.
2. **Production extraction option if justified.** Separate a last-output-hidden flag from `cparams.embeddings`. Allocate and copy one hidden row alongside normal logits; keep LFM2 vocabulary projection enabled, normal output mask and pooling none. Include the flag in graph-reservation/reuse identity and test off/on transitions. Reusing existing `embeddings=true` globally would request all token outputs and suppress LFM2 logits; it is not the required change.
3. **Pre-sampling adapter boundary.** Retain the prefilled slot in the same process while a bounded existing external head computes its approved delta, or run that exact approved external head natively. No new automatic approval or model-generated tool authority. A prepare/resume design needs a single-use source/context-bound handle, TTL, owner identity, bounded rows/bias and cancellation/pressure cleanup. Merely calling `/completion` twice after unrelated slot work is not same-prefill authority.
4. **Baseline probability measurement.** Read actual pre-sampling logits from the same selected output. For training, preserve the full-vocabulary normalization and remaining-mass semantics; returning only top-k renormalized values changes the objective. Native log-sum-exp plus selected-row values could avoid transporting 65,536 JSON probabilities, but must prove equivalence against the existing full distribution, including underflow and all finite values. No such optimized endpoint currently exists.
5. **Fallback and artifact identity.** Feature semantics/port ID must identify causal live generation versus existing separate tap. If feature parity fails, do not reuse approved old adapter weights as if compatible: recollect/retrain the same preregistered sources, fixed retention/calibration/individual approval. Missing live capability uses the existing honest path, never a fabricated vector.

The callback route is a potential minimal *research* patch, not a promised optimal production design. It may synchronize backend execution and cannot by itself guarantee Android latency. A direct extraction patch needs a new reproducible runner artifact/hash/build manifest; the unchanged pinned binary cannot suddenly advertise a port it lacks.

## Required parity and resource proofs

- Same exact template/token IDs, causal mask, positions, initial attention **and recurrent** state, output index, 1024D shape and raw final RMSNorm; compare all finite hidden coordinates and first-position 65,536 logits/probabilities under preregistered absolute/relative tolerances. Exercise 1/34/127/128/129/193/511/512-token contexts and generation chunk boundaries, repeated prefixes, empty/malformed/mismatched inputs and context admission refusal.
- Read-only port off/on must leave greedy baseline first token and full continuation unchanged. Test zero delta, actual approved nonzero first-position delta, later positions unbiased, fixed old-case retention, rollback/restart and unchanged GGUF hashes. Sampling seed alone is not a guarantee of equal stochastic output across changed backend topology.
- Same process identity and prompt slot must persist from prefill through first token and continuation. Record actual cache-token counts; exact repeated prompt, suffix extension and changed prefix/rule/context must exercise cache admission/invalidation. A full-cache reuse may recompute a final token: verify its output position/state rather than assuming a callback fires on the old final row. No persisted native KV restart capability follows from retaining one live process.
- Failure between prefill and resume, stale handle, cancel/deadline, new higher-priority input, malformed native response and critical resource pressure must visibly terminalize once, release any pause and reap/clear native state. Final hidden reads are not an exemption from the existing deadline/first-cause/resource guards.
- Measure paired adapter off/current separate tap/new live port on the same source, history, rules, generation and native artifact: ingress→first visible output, load/template/prefill/head/sampling/stream timings, callback synchronization overhead, process changes, cache hits, sampled RSS/PSS and independently measured KV/recurrent bytes if exposed. Run sustained repetitions on the actual Redmi before adopting residency/batch changes; Linux RSS is not phone headroom or a KV-size estimate.

Each of the 26 held-out consumers reports a distinct resolved generation process PID and zero cache tokens for its first biased step. Subsequent unbiased continuation reuses **193–198** prompt-cache tokens within that newly loaded process. This is evidence of retained cache *within the two-step generation*, not cache retention across the earlier embedding→generation switch.

Tap `duration_s` excludes the explicit preceding `runner.load`; the prepare window also includes template/local-head/packet work. Generation load wall time includes health polling. Adding or subtracting these medians is not a measured counterfactual speedup. The data substantiate repeated loading and duplicate prompt work, with bounded actual Linux timings; they cannot predict Redmi gains, battery/thermal behavior, native KV size or that a callback eliminates all overhead. The appropriate next experiment is the controlled native port proof above, not a cosmetic response change or a new pipeline layer.

## Isolated prototype prepared after this audit

Root subsequently authorized preparation/compilation of an isolated read-only native port experiment. `docs/proofs/native_live_prefill_port.cpp` now contains actual public C API code, compiled with the exact b10964 headers and installed release libraries under `-Wall -Wextra -Werror`. `docs/proofs/native-live-prefill-compile-20261008.json` records source/binary/compiler/library hashes and dynamic-link resolution. The first failed compile is retained in its own log; the exact pinned vendor SHA include path and two strict indentation diagnostics were fixed. **Compilation is not a native inference or parity proof. The executable has not been invoked.**

The binary is reproducible transient cache at `native/tmp/live-prefill-prototype/native_live_prefill_port`. It accepts unique `--key value` arguments. Required: `--model`, `--tokens`, `--output`, `--model-sha256`, `--lib-sha256`. Token input is a JSON object containing actual `token_ids` from the existing exact-template runner; no tokenization replacement is built into this prototype. Optional: `--mode live|baseline|embedding-counter`, `--n-batch`, `--n-ubatch`, `--ctx`, `--threads`, `--continue`, `--seconds`. Tokens are bounded at 512, continuation at 8, deadline at 120 seconds, CPU threads at 8; native CPU abort and SIGINT/SIGTERM cancellation are configured. Loaded actual GGUF and llama library must match supplied hashes before model loading. The report includes actual input IDs, input-file hash, loaded llama/ggml libraries, tensor shapes/strides, decode return codes, batches and elapsed time. `live` copies native `result_norm` through the graph callback and obtains the full first logits/probabilities from the same final decode. `baseline` disables the observer for counterfactual numerical comparison. `embedding-counter` obtains the actual embedding state but refuses a vocabulary distribution because no output projection was computed. Greedy continuation uses the same live context; this does not implement HTTP slot reuse or persistent KV.

A subtle counterproof guard is deliberate: pinned `output_reserve()` allocates a logits host buffer even in embedding mode. `llama_get_logits_ith()` may therefore expose a non-null pointer without a computed LFM2 `t_logits`. The prototype never treats this pointer or arbitrary allocated bytes as a native vocabulary distribution. It observes absence of `result_output` and reports `logits_computed=false` instead.

Next slot experiment: export an exact >128-token production context through the existing runner; run observer-off baseline, live observer, and 512/512 embedding counter sequentially on those same IDs and immutable hashes; compare every finite state coordinate, cosine/norm/max absolute and relative error, full-vocabulary distributions, greedy first token/continuation and decoder chunk-boundary records. Then repeat context lengths across the native 128-token boundary and compare with the existing separate C3 HTTP tap. Preserve numeric failures and raw arrays; no zero-state fallback, gate weakening or automatic old-adapter reuse. There are no runtime/harness/config integration edits in this prototype.
