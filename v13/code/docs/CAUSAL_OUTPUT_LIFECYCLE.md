# Same-causal output adapter lifecycle

This additive path uses the existing `output_adapter` component, F5 permissions and Generation approvals. The package contains no genuine end-user labelled same-causal head. Software fixtures prove lifecycle/control behavior; native learned output and useful-answer quality remain separate gates.

While the coordinator is idle:

```text
:decode server
:decode same_causal_zero
:decode same_causal
```

Changes unload existing output residency and persist after restart. Causal modes require the exact prepared native worker and64/128 output-token limits. `same_causal_zero` always sends zero bias. `same_causal` permits an individually approved current-ABI head; missing, incompatible, revoked or unsupported heads return to zero. An admitted head computes a bounded first-position delta from the actual checked same-prefill feature. All remaining positions continue unbiased in that native context.

The established reference capture/assembly exporter requires original typed `:feedback output ... --learn` plus explicit learn reexport. Its actual native feature, complete vocabulary distribution, exact context/IDs and label tokenizer receipts remain bound to the original human source. Model text is never converted into human permission.

With a sufficient exported cohort and chat closed:

```bash
python3 scripts/train_live_output_adapter.py --dataset /absolute/cohort/dataset.json --out /absolute/new-fit
```

The unchanged numerical trainer enforces source-disjoint split/per-class counts, gradient, calibration, utility, first-token accuracy, support and retention gates. In the running chat:

```text
:learning shadow
:import causal-output /absolute/cohort/dataset.json /absolute/new-fit
:requests
:learning commit
:approve <exact-update-id>
:decode same_causal
```

Import runs as an existing coordinator job. It privately copies exact bound artifacts, checks original/current F5 decisions byte-for-byte against this Store, current latest learn permission, source/context/model revisions and actual export links, then independently replays the unchanged offline numerical fit with the current F7 shadow budget. Imported candidate bytes must match that replay; asserted good report metrics cannot replace it. The job can be cancelled without changing the active generation.

Successful gated fits become `PENDING_APPROVAL`; numerical failures remain `EVALUATED_FAIL`; interrupted/rejected verification is preserved as `ABORTED`. Approval requires `APPROVED_COMMIT` and the concrete update ID. Operator and direct Store approval both check actual artifact/report hashes, unchanged dataset/numerical worker receipts, exact prepared ABI/consumer revision, current source/permission lineage and retention parent. Every consume rechecks individually committed ownership and current source/permission/encoder/ABI identity.

Separate-prefill heads are never converted or loaded here. Roll one back before starting a new causal lineage. Further same-ABI training must retain the current approved checkpoint and previous held-out cases.

```text
:rollback <last-active-update-id>
:decode same_causal_zero
```

Rollback uses existing Generation ancestry and preserves unrelated rules. A later record-only correction supersedes the old learn reference, causing zero fallback. Existing forgetting requires rollback before removing sources embedded in active weights, then quarantines dependent candidates. This does not claim arbitrary neural unlearning.

Actual per-turn `observed.json` is saved immediately after checked native pause, before resume, with its exact SHA in turn metadata. It is actual protocol output, never reconstructed from answer text. Raw per-turn diagnostics retain the existing last-eight completed-directory cap; exported permanent proofs/checkpoints and Store sources are separate.

Recovered proof artifacts live in `docs/proofs/causal-output-lifecycle-20261009/`. Tests use explicitly synthetic native numeric data with real isolated SQLite source/F5/Generation operations. They do not establish a genuine user cohort, native learned quality, body-weight updates or Redmi performance.
