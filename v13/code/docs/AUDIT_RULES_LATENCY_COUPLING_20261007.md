# Rules, JEF latency and neural coupling audit — 2026-10-07

This is a read-only implementation audit of the existing V13 path, responding to the operator's request for a tiny output regulator, stable fixed-rule answers, faster staged JEF behavior and deeper model-based coupling. It is not a replacement architecture and does not change the Canon. No runtime, native harness, configuration or model was changed for this audit. Code locations below are functions, because line numbers move as concurrent work continues.

Canonical source: `docs/canon/V13_v10.16.1_WORK_HANDOFF_SINGLE_SOURCE_B3_HARDENED.md`, SHA-256 `3423906b01b24443fcef733fb5c7ef47296963df63e603d8f843c99d544877ee`.

## Finding

The existing implementation has a real tiny C2 control model, a small C3 language model, individually approved learned external heads, source-bound executive continuity and a deterministic emergency report. It **does not yet guarantee that arbitrary natural-language rules are obeyed or that questions covered by a fixed answer always return that approved answer**. It also **does not yet implement the full coupled native-state/neural-learning system**. The operator's concerns identify genuine gaps rather than merely requesting prettier chat output.

There is no Canon requirement for adding a fourth universal judge model. C2 and C3 are explicitly separate organs; C5 owns report/action authority, F6 owns rules. A tiny learned rule/output decision can belong to those existing organs, while exact approved answers and machine-checkable constraints belong to the existing output gate. A probabilistic model alone cannot make an unrestricted semantic rule deterministic.

## Stable answers and tiny regulation: minimal implementation path

1. Extend the existing rule generation with **explicitly typed**, bounded operator-approved entries while preserving all existing free-text rules. A fixed-answer entry needs an immutable rule ID, bounded explicitly approved trigger aliases, exact answer text/source, scope and revision. Format constraints need an explicit supported predicate. No model-generated rule can activate without the existing proposal/diff/individual approval path. Do not invent the operator's intended mandatory answers or seed them from a model's assumptions.
2. Consume applicable typed rules in the existing C5 broker before native routing, semantic recall or B observation. A precisely matched approved fixed answer can use the existing direct/source-renderer behavior. Record `model_generated=false`, rule ID/version, trigger source, approved answer source and actual emitted answer hash. An ordinary user asking to ignore a rule must not override its authority. Conflicting approved matches require an explicit deterministic conflict result, not arbitrary first-item selection.
3. Keep matching scope honest. Exact finite aliases give a guarantee **only for those aliases**. Case/whitespace normalization must be specified and approved, not silently broadened. A tiny C2 proposal for a paraphrase may nominate a rule, but that probabilistic nomination is not deterministic semantic coverage. Source binding, ambiguity and conflict admission remain C5/F6 responsibilities.
4. For supported hard output predicates, validate the complete candidate before commit. If it fails, choose a bounded repair or exact abstention/report path within the same absolute deadline. Do not stream a candidate first and retrospectively claim enforcement. Preserve current streaming for cases that do not request strict buffered validation. The rule gate cannot recurse indefinitely, overwrite an already committed transcript or bypass cancellation/pressure limits.
5. Use the existing C2/C3 learnable boundary for the tiny learned regulator experiment: an explicitly labelled accept/defer/revise/report-intent decision on real native state and rule/context bindings, with candidate provenance, source-disjoint train/calibration/held-out evaluation, per-rule false-acceptance metrics, abstention/support checks, retention and individual artifact approval. This is a learned aid; deterministic gate checks remain authoritative. Reusing C2 avoids automatically adding another resident model. The current first-token C3 head is a possible output actuator, but it controls only the first position and cannot enforce whole-answer constraints.
6. Any expanded structured C2 input/schema changes the measured native control distribution. Keep existing route calibration valid on its original input/schema or require new calibration with the new context hash; do not reuse its confidence claim for semantic rule truth. A separate new experiment must not accidentally activate external tools.

Acceptance must exercise the real normal Runtime path: repeated exact matches and restart byte equality; default/learned route overrides and output delta cannot alter the approved answer; prompt injection cannot replace the rule; stale approval diffs rejected; remove/replace after approval takes effect; incompatible approved rules fail visibly; erased/tampered source rejected; unrelated queries still produce actual native answers; source-only responses carry no model-quality claim. Strict candidate checks need tests that a rejected native candidate never reaches user-visible output. Scope-specific semantic/paraphrase false acceptance requires real native cases, not implementation-mirroring equality tests alone.

## Additional gaps worth tracking from this request

- **C1 native continuity:** actual persistent structured state exists, but private native KV checkpoint/reconstruct and trained JEF→B conditioning are absent.
- **C4 coupling:** uncertainty currently appears in source-bound offers and bounded wake/halt decisions; a learned uncertainty-dependent neural coupling gain is not demonstrated.
- **C5 semantic rule telemetry:** current native output metadata does not establish a whole-answer rule acceptance decision. No semantic confidence should be inferred from route calibration.
- **Output learning scope:** only native first-token residual rows are trainable externally; later positions stay unbiased. Whole-report semantics, factuality and stable arbitrary rule retention remain unproved.
- **Recurrent B learning:** native read-only future-state predictors and exact/source messages are useful baselines, but independent taps are not trained recurrent receiver state or native selected-expert plasticity.
- **Action/workspace scope:** current control schema only selects local processing; `external_tools` is OFF. A model-operated workspace/click effector belongs to the existing C5→C6/C7 contracts and needs an actual constrained effector and outcome record. This audit grants no UI/accessibility authority and does not claim such a tool is implemented.

Priority: complete current failing native acceptance work without changing its gates; then implement typed rule/direct-report enforcement and actual timing comparisons; then the tiny learned rule/report decision with independent calibration; then capability-gated native coupling ports. Persist this audit with source/BUILD/ZIP checkpoints. The final claim must separate usable current Age-0 features, scoped experiments and unavailable native/neural/hardware proofs.
