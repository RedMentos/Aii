## Problem, primary evidence and hypothesis

Run14L pinned 350M native C3 protocol returned 8/8 markdown-fenced `VERIFIED_FACTS` arrays and 0/8 strict six-field JSON objects in its structured arm, versus 4/8 source-faithful copy baseline. The existing native `v13/runners.py` `Runner.generate(...,schema=...)` passes `json_schema` to llama-server `/completion`, but Run14L did not use that argument. Official ggml-org/llama.cpp server README (accessed 2026-10-30, https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) documents schema-constrained JSON; the official model card (https://huggingface.co/LiquidAI/LFM2.5-350M-GGUF) identifies the LFM1.0 license. This supports a *syntax* hypothesis only, not improved semantic fidelity. A 2025 llama.cpp issue #11988 about chat response_format was fixed; our path uses the native /completion json_schema field, not chat response_format.

No extra samples or retries. Predeclared positive syntax signal: constrained arm improves valid-six-field JSON by **at least 4/8**, all 16 calls FINAL and reaped, and no fewer strict all-six-exact outputs than prompt-only. Else `NO_BOUNDED_SCHEMA_SIGNAL` or `SCHEMA_HURT`; no gate promotion even on positive signal.
