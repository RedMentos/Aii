## Question

Run11S source-only selector parses the **note value**, then returns its **note key**. It does not prove that the selected key's project, month, and note kind agree with the parsed value. A mismatched key/value pair can be selected and later treated as a source pointer for a different note. It also uses the first `Project X` mention in the query even if another distinct project appears.

## Separate candidate and disjoint evaluation

Implement a separate read-only `focal_source_identity_guard_run11u.py` wrapper. It calls frozen Run11S `propose` unchanged, then checks that every selected source key is bound to the same project, month (when applicable), and note kind as the parsed value. For update/combine/correction, a mismatch **abstains** with zero selected keys and a typed reason. A query mentioning two distinct projects also abstains. For unsupported shapes, preserve the existing abstention. Distract mode needs no stored note; do not turn it into model output or an authoritative answer.

Preregister fresh disjoint **seed173**, four original task kinds ×15 = 60 source-only fixtures generated by frozen `tasks`. Capacity4. Compare source-key inclusion/exactness to frozen independent `required_keys` oracle, and compare wrapper to original selector on **unaltered** fixtures. Record both exact and required-included metrics; no model answers.

Adversarial tests (fixed before source): key/value month mismatch; selected key project mismatch; selected key kind mismatch; spending key/body mismatch; correction key/body mismatch; multiple query projects; source text injection; unsupported query; duplicate keys; invalid capacity; no input mutation; distract unchanged. Also test a foreign-project note not selected and a benign original note passes. A correct guard must abstain on all altered selected source identities and must not silently fall back to an unverified selected key.
